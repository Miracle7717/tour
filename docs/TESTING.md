# Тестирование отправки данных API

Автоматические API-тесты находятся в `tours/tests.py`. Они используют Django REST Framework `APITestCase`, тестовую базу данных и JSON-запросы. Для запуска:

```powershell
python manage.py test tours
```

Для документации конкретных форматов запросов и ответов откройте Swagger UI на `/api/docs/` или схему OpenAPI в [`openapi.yml`](./openapi.yml). Примеры тел запросов в Swagger описаны рядом с операциями записи и проверяются тестом `test_api_documentation_endpoints_are_available`.

## Проверки операций записи

| Endpoint | Успешная отправка | Негативные проверки |
|---|---|---|
| `POST /api/auth/register/` | Создание пользователя и профиля 1:1; пароль сохраняется хешированным и не возвращается | Короткий пароль и повторный username |
| `POST /api/categories/` | Создание категории администратором | Запрос без прав администратора; повтор имени/slug |
| `PUT`, `PATCH`, `DELETE /api/categories/{id}/` | Полное и частичное обновление, удаление категории администратором | Проверка корректных ответов и сохранённых значений |
| `POST /api/tours/` | Создание тура с несколькими категориями M:N | Запрос без прав; пустое название; отрицательная цена; нулевая длительность; отсутствующая категория |
| `PUT`, `PATCH`, `DELETE /api/tours/{id}/` | Полное и частичное обновление, изменение списка категорий, удаление тура администратором | Проверка ответов и итогового состояния базы |
| `POST /api/bookings/` | Создание бронирования, повторная запись на другое время, запись после отмены | Неавторизованный пользователь; несуществующий или снятый с публикации тур; отсутствующее время; два активных тура на одно время |
| `POST /api/reviews/` | Один или несколько отзывов к собственному завершённому бронированию | Неавторизованный пользователь; незавершённое или чужое бронирование; рейтинг за пределами 1–5; пустой комментарий |

Уникальность активного бронирования дополнительно проверяется напрямую на уровне базы данных — это защищает от дублирования при одновременных запросах.
